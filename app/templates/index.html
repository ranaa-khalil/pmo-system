1. System Overview

The PMO System is a project management office platform built for Obelion. It manages the full delivery lifecycle — from vision and requirements through release and post-release monitoring — using a V-model (V-cycle) approach aligned with the RACI matrix.

Tech Stack
FastAPI + Jinja2 (SPA) + Alpine.js + Tailwind CSS + SQLite
Authentication
JWT-based, 4 system roles, 12 RACI roles per project

2. Roles & RBAC

The system has two role layers: system roles (control what you can do globally) and RACI roles (control what you can do per project, aligned to the RACI matrix).

System Roles
super_admin Full access to all features. Can manage all clients, projects, users, and settings.
account_manager Can manage clients and projects they're assigned to. Can create projects and assign PMs.
project_manager Manages their assigned projects — backlog, releases, milestones, KPIs, stakeholders.
member Basic access. Can view assigned projects and complete assigned tasks.
RACI Roles (12 — per project)

RACI roles are assigned per project via the Stakeholders tab. They determine who receives approval requests at each phase gate.

5. Backlog Management

Items are grouped by Epic. Each item has an item-level phase lifecycle that stops at "Ready for UAT" — after that, the release drives the phase.

Item-Level Phases (5)
Send Back
From Testing, an item can be sent back to Development (status = In Progress). This allows QA to reject items that fail testing.
Filters
Phase filters: Requirements, Design, Development, Testing, Ready for UAT
In Release: Items in UAT or Pre-Release (in a release but not yet deployed)
Released: Items in Release, Post-Release, Retrospective, or status=Done
Progress Bar
When an item enters a release-level phase (UAT+), its item-level progress bar turns all green — all 5 item phases are complete. The release-level progress bar (emerald) shows position in the release lifecycle.

6. Release Management (V-Cycle)

Releases follow a 7-phase V-cycle. Each phase has a gate-keeper role that must approve before the release can advance.

V-Cycle Phases (7)
How it works
  1. Release starts at "Planning" with SemVer auto-numbering (e.g., 1.0.0)
  2. Click "Advance" to trigger the gate approval for the current phase
  3. The gate-keeper role receives an approval request in the Approvals tab
  4. When approved, the release advances to the next phase
  5. All linked backlog items are automatically synced to the new phase
  6. The cycle continues until Post-Release

7. Approvals & Sign-Offs

When a release advances, an approval request is auto-created and routed to the user who holds the gate-keeper RACI role on that project. No manual forms — the system handles it automatically.

📋
Auto-Routing
Approval step is assigned to the user with the matching RACI role (e.g., Tech Lead for the In Progress gate).
☑️
Checklist Auto-Check
Each gate has 3-5 checklist items that are automatically evaluated against actual release data (items linked, phase progress, release notes, etc.).
✅
Approve / Reject
The assigned user approves or rejects. On approval, the release auto-advances and the next gate approval is created.

8. Docs & PDFs

The Docs tab (per project) lists all releases with their sign-off documents. Each release generates a PDF containing:

  • Release info (project, version, status, dates)
  • Phase gate summary table (gate, role, status, approver, date, checklist progress)
  • Detailed checklists per gate (each item marked [x] or [ ])
  • All release items with their phase and status
👁 View — opens PDF in an inline viewer modal
⬇ Download — saves the PDF file

Release notes can also be generated as DOCX files from the release detail modal.

RACI & Stakeholder Management

This tab manages who is involved in this project and what role they play. The RACI roles follow the RACI Matrix v2.3 from the Release Process. Assign the 6 required gate-keeper roles first (below), then add external stakeholders (clients, partners) who need to be informed or consulted.

① Required Roles for Release Process

These 6 roles must be assigned before a release can advance through V-cycle approval gates. Search and assign a user to each.

These roles are required as per the Release Process V-cycle approval gates. Assign each role to a team member in the Settings tab before planning a release.

② Assigned Team Members

System users who have been assigned a RACI role on this project. These are the people who will receive approval requests when a release advances through the V-cycle.

③ Add External Stakeholder

Add people outside the system (clients, partners, sponsors) who need to be Consulted or Informed about this project. They won't have system access but will be listed in the RACI matrix and can receive shared release notes.

④ RACI Legend

From RACI Matrix v2.3 — used to classify each person's involvement in project activities.

R
Responsible — does the actual work. Can be more than one.
A
Accountable — single owner with sign-off authority. Exactly one per activity.
C
Consulted — provides input before/while work is done. Two-way.
I
Informed — kept up to date on progress or outcome. One-way.
